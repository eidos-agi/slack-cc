Cerebro Authentication Upgrade

Securing financial data access with individual accounts and Microsoft SSO
Prepared by: Daniel Shanklin Date: March 2026 For: Michael Nguyen, Alex Kaye

The Problem

Security Gap

Cerebro currently uses one shared password for all 8 users. There is no way to know who logged in, no way to revoke one person's access without changing everyone's password, and no two-factor authentication.

This is manageable while Cerebro only shows operational data. But we are about to connect Sage Intacct — which means real financial data (revenue, invoices, AR aging, P&L) will be visible in the dashboard. A shared password is not acceptable for financial data access.

The Solution

We'll upgrade authentication in three phases. Each phase builds on the previous one, and each can be rolled out independently. There is no disruption to the dashboard itself — only the login experience changes.

Phase 1: Individual Accounts

Every user gets their own login — an email address and a personal password. When they first log in, they'll also set up two-factor authentication using an authenticator app on their phone (Microsoft Authenticator, Google Authenticator, or similar).

What changes for users

  • + Each person has their own email/password — no more sharing credentials
  • + Two-factor authentication required — a 6-digit code from your phone at each login
  • + Audit trail — we can see who logged in and when, including failed login attempts
  • + If someone leaves, we disable their account — no need to change everyone's password
  • + Automatic session timeout — if you walk away from your desk, Cerebro logs you out after 30 minutes of inactivity

Why two-factor authentication matters

If a password is ever stolen from another website (and reused here), 2FA is what stops an attacker from using it to access Cerebro. It's a simple, powerful defense against the most common type of cyberattack — stolen credentials.

What doesn't change

The dashboard itself is identical. Same data, same pages, same experience. Only the login screen is different.

Effort: ~2 days of development. No downtime. Each user receives a personal email invitation with setup instructions.

Phase 2: Add Microsoft Login

Greenmark already uses Microsoft 365. In Phase 2, we add a "Sign in with Microsoft" button to the login page. Users can click it and authenticate with their existing @greenmarkwaste.com Microsoft account — the same credentials they use for Outlook, Teams, and SharePoint.

Why Microsoft

  • + Users already have Microsoft accounts — no new passwords to remember
  • + Microsoft handles 2FA — if you have Authenticator set up for Outlook, it works here too
  • + Restricted to @greenmarkwaste.com only — personal Microsoft accounts cannot log in

Email/password login still works as a fallback during this phase. Both options are available.

Effort: ~1 day of development. Requires an Azure AD app registration (see "What We Need From You" below).

Phase 3: Microsoft Only

Once all users are comfortable with Microsoft login, we disable email/password entirely. Microsoft SSO becomes the only way to access Cerebro.

Why this matters

  • + Zero passwords to manage — when IT creates or deletes a Microsoft account, Cerebro access is handled automatically
  • + Offboarding becomes automatic — disable the Microsoft account, Cerebro access ends immediately
  • + Compliance-friendly — single sign-on with audit trails through Microsoft's security center

Emergency access

We will create one emergency admin account stored offline in a physical safe — independent of Microsoft. Think of it as the emergency key to the building. If Microsoft ever has an outage, this account guarantees we can always get in. Two trusted people will have access to this key.

Effort: Half a day. Flip a configuration flag and update the login page.
